- `server.py`'s guard pattern matches design.md's Interfaces/Contracts section's `_ONENOTE_PRESENT` example, generalized to all 5 families and extended to also guard each family's Port-type import (`CalendarPort`/`TaskPort`/`MailPort`/`FileSearchPort`/`OneNotePort`), falling back to `typing.Any` — design.md's own snippet only showed the tool-callable fallback; the Port-type fallback was a necessary completion since `create_server()`'s parameter annotations reference these names at function-definition time (no `from __future__ import annotations` in this file) and would otherwise raise `NameError` when a family is absent.
- `_tool_enabled()` folds family-presence directly into the same closure that checks shipped/installed, per design.md's Data Flow section's formula (`_FAMILY_PRESENT[family_of(name)] and (shipped is None or ...) and (installed is None or ...)`) — implemented as a single dict lookup (`_FAMILY_PRESENT_BY_TOOL`) rather than a `family_of()` helper function, since the mapping is small and fixed (13 entries).
- `make-deploy-package.sh` keeps `MANIFEST` as the full, unfiltered source-of-truth array (used only by Gate 1's — now `STAGED_MANIFEST`-based — existence check is actually against the filtered set per the batch instruction "Gate 1 must respect per-mode staging"); introduced `STAGED_MANIFEST` as the actually-staged/actually-checked derived array so a share build's omission is threaded consistently through staging, Gate 1, and Gate 7's `MANIFEST_LIST` input.
- Gate 7's excluded-files negative check recomputes `excluded_files(catalog, selected)` directly in Python (re-importing `tools.catalog`) rather than threading the bash `EXCLUDED_FILES` array through another temp file — simpler, and guarantees the check uses the exact same function under test as the staging step.
- Fixed a real catalog gap surfaced by task 3.3's completeness check: `file_get_info` was missing `tools/file_search_walk.py`. This is the same class of oversight already flagged in the file family's `ps_bridge_transport.py`/`ps_bridge_search.ps1` comment (the 2026-08-28 predecessor fix) — harmless while every file always shipped, load-bearing under hard exclusion. No test hardcoded the old (incomplete) dep list, so fixing `catalog.yaml` directly was safe.
- Batch 4 (task 4.5): chose a `ModuleNotFoundError`-shaped bug (a stray internal import inside a present module) over the orchestrator brief's literal `SyntaxError` example, because `SyntaxError` is never an `ImportError` subclass and so cannot distinguish the correct `find_spec` guard from the exact `try/except ImportError` anti-pattern the test needs to catch — empirically verified before committing to this design (see task 4.5 note and the Issues Found section below). This is a "design your own if better" deviation the batch instruction explicitly permitted, not a shortfall against the assigned scope.
- Batch 4 (task 4.6): mirrored check 5's existing per-entry module-closure loop shape exactly for `.ps1` references (same `for entry: for dep in entry["deps"]["modules"]` loop, same open-once/reuse-`dep_src` pattern, same "skip if not catalog-tracked" guard) rather than introducing a separate pass — keeps the two completeness checks visually and structurally parallel for future maintainers.

## Issues Found

- **`tools/catalog.yaml`**: `file_get_info`'s `deps.modules` was missing `tools/file_search_walk.py` (see above) — fixed as part of Batch 2, verified live via the `--share --tools=file_search,file_get_info` build (the file is now correctly staged).

Not part of this change's assigned tasks (Phases 2-4); flagging again for a future cleanup, not fixed here — it's a manifest-hygiene nit unrelated to the hard-exclusion ceiling itself (fakes are never registered as tools either way).

- **Batch 4 finding (not a defect, a design-choice discovery)**: while designing task 4.5's regression test, empirically confirmed that a plain `SyntaxError`-based bug in a present family module propagates identically whether `server.py`'s guard is the correct `find_spec`-gated form or the exact `try: from tools.X import ... except ImportError: ...` anti-pattern the test needs to catch — because `SyntaxError` is never an `ImportError` subclass, so `except ImportError:` never intercepts it either way. A `SyntaxError`-based test would therefore be GREEN under both the correct guard and the regression, providing no actual protection. Switched to a `ModuleNotFoundError`-shaped bug (a stray internal import inside the present module referencing a genuinely nonexistent module), which IS an `ImportError` subclass and IS swallowed by the anti-pattern — confirmed both directions live (see task 4.5 above). Documented here so a future reader doesn't "fix" the test back to a `SyntaxError` example thinking it's more literal to the original ask.
- **Batch 4 finding**: task 4.6's negative-case verification required a temporary in-place edit to the real `tools/catalog.yaml` (backed up first, restored immediately, diff-confirmed byte-identical) because `make-deploy-package.sh` hardcodes `CATALOG_YAML="$ROOT/tools/catalog.yaml"` with no flag to point it at an alternate/scratch catalog file. Per the batch instruction's explicit fallback ("if the script can't target an alternate catalog, verify by temporary in-place edit RESTORED immediately"), this was the intended verification path, not a workaround of last resort. No lasting change to `catalog.yaml`.
- **No production runtime code changed in Batch 4** — both tasks are test/tooling-only (a new pytest regression test + a new build-gate check); `server.py`, `tools/catalog.py`, `tools/settings.py`, and `catalog.yaml` are all unchanged at the end of this batch.
